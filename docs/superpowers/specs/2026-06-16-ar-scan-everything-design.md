# 万物皆可扫：现实物品的 AR 奇遇记 —— 设计文档

- 日期：2026-06-16
- 状态：Draft（待评审）
- 形态：移动端 H5 PoC

## Context

"扫一扫"目前只面向二维码、条码这类标准化标识。本 PoC 想把它的边界拓宽到日常物品本身——用户随手拍一张缺口杯、闲置鞋、蔫绿植，就能得到一段以物品第一人称写的趣味日记，并自然落到一个对它最合适的平台服务（购物 / 本地生活 / 二手 / 保养贴士）。

目标是验证三件事能否串起来：

1. 视觉大模型能不能在一次调用里同时完成"识别 + 物品状态判断 + 拟人化写作 + 服务匹配"
2. 服务推荐能不能跟物品状态强相关（缺口杯 → 换新；旧电视 → 回收；蔫绿植 → 浇水贴士）
3. 整套流程能不能在手机网页上跑通核心闭环

非目标：账号体系、收藏/历史、真实下单、AR 实景叠加、多语言、性能与并发优化。

## 系统架构

三段式：**H5 前端 → 轻量后端代理 → Claude 视觉**。

```
[H5 拍照/选图] --base64图--> [Node 代理 /api/scan] --vision--> [Claude]
       <--日记+推荐 JSON-----        <----结构化 JSON----
```

- 前端是单页 H5（vanilla HTML/CSS/JS，开发期用 Vite 做静态托管 + 移动调试），使用 `<input type="file" accept="image/*" capture="environment">` 唤起相机/相册，把图片压到 ≤ 2MB 后 base64 上传
- 后端用 Node + TypeScript（`tsx` 直跑，免编译），只做一件事：藏住 API 密钥、拼好 prompt、把 Claude 的回复转成稳定的 JSON 给前端
- 一次 Claude 请求同时产出：物品名、状态、第一人称日记、服务类型、推荐文案与关键词

### 模块边界

| 模块 | 职责 | 依赖 |
|---|---|---|
| `web/` H5 页面 | 拍照、压缩、上传、渲染日记+服务卡 | 仅依赖 `/api/scan` |
| `server/` Node 代理 | 校验入参、调用 Claude、解析+兜底 JSON | Claude SDK、环境变量里的密钥 |
| `server/prompt.ts` | Prompt 模板与 schema 描述 | 无外部依赖 |

每个模块单独可懂、可测：前端可用 mock 后端跑通三屏；后端可用单测 mock Claude 验证解析与兜底。

## 数据契约

### 请求

```http
POST /api/scan
Content-Type: application/json

{ "image": "data:image/jpeg;base64,..." }
```

- 大小：≤ 2MB（前端先压）
- 格式：jpeg / png / webp

### 成功响应（200）

```json
{
  "object": {
    "name": "陶瓷马克杯",
    "state": "杯口有缺口、有使用痕迹"
  },
  "diary": "今天又被主人捧在手心，可惜杯口那道伤一直没好……",
  "recommend": {
    "type": "ecommerce",
    "title": "该换个新杯子啦",
    "reason": "杯口缺损会割嘴，建议换新",
    "keyword": "陶瓷马克杯 简约",
    "cta": "去看看"
  }
}
```

字段约束：

- `diary`：第一人称、≤ 100 字（中文按字符计）
- `recommend.type`：枚举 `ecommerce | local | resale | tips`
- `recommend.keyword`：电商/本地/二手类用于拼搜索 URL；`tips` 类可为空
- 整体大小：≤ 4KB

### 错误响应

```json
{ "error": { "code": "BAD_IMAGE", "message": "图片过大或格式不支持" } }
```

| code | HTTP | 触发条件 |
|---|---|---|
| `BAD_IMAGE` | 400 | 缺字段、非 data URL、超过 2MB |
| `MODEL_FAILED` | 502 | Claude 报错、或返回内容抽不出 JSON |
| `INTERNAL` | 500 | 其它未捕获异常 |

## 服务匹配规则（Prompt 中描述给模型）

模型按物品+状态从下表中选 **恰好一条**：

| type | 适用场景示例 |
|---|---|
| `ecommerce` | 物品损坏/缺失/明显老化，建议换新 |
| `local` | 大件家电/家具不便处理，建议上门回收/清洗/维修 |
| `resale` | 物品状态完好但用户可能闲置，建议二手出售 |
| `tips` | 不需要消费，给一条养护/使用小贴士（如蔫绿植浇水） |

兜底：模型若识别不出物品（`object.name = "未知物品"`），固定走 `tips` 类型，文案为通用提示。

## 界面与交互

三屏：

1. **拍照 / 选图屏**：满屏取景占位 + 取景框 + 底部三键（相册 / 快门 / 闪光）；不实际接 getUserMedia，靠 `<input capture>` 在系统层完成拍摄
2. **扫描中屏**：物品预览图 + 一道扫描线动画 + "AI 正在阅读……"，等待后端响应
3. **结果屏**：物品缩略图 + 识别标签 + 日记卡（暖白底 + 大字日记 + 引号点缀，整体走橙色主色调）+ 服务卡（按 `type` 着色与图标，CTA 按钮）

服务卡点击行为：

- `ecommerce` → 跳淘宝/京东 H5 搜索（`https://s.taobao.com/search?q=<keyword>`）
- `local` → 跳美团/58 服务搜索 H5
- `resale` → 跳闲鱼搜索 H5
- `tips` → 不跳转，原地展开完整贴士

## 错误处理

| 场景 | 表现 |
|---|---|
| 图片过大 / 格式错 | 前端拦截，弹"换张图试" |
| 网络失败 / 后端 5xx | 结果屏显示"AI 走神了，再试一次" + 重试按钮 |
| Claude 返回非 JSON | 后端用正则抽首个 `{...}` 块；仍失败返回 `MODEL_FAILED` |
| 识别不出物品 | 走 `tips` 兜底模板 |

## 测试范围（PoC）

- **后端**：两个单测——happy path（mock Claude 返回合法 JSON，断言透传字段）+ 容错（mock Claude 返回带前后噪声的字符串，断言能抽出 JSON）
- **前端**：不写自动化测试；手动跑通三屏 + 服务卡四种 type 的渲染
- **端到端**：用三张样图（缺口杯 / 蔫绿植 / 旧鞋）人工验证服务类型分布合理

## 验证方法

1. `cd server && npm install && npm test` —— 两个单测通过
2. `npm run dev` 同时拉起后端（默认 3000）与前端静态服务（默认 5173）
3. 手机与电脑同 WiFi，浏览器打开电脑 IP:5173；或用电脑浏览器开"移动设备模拟"
4. 依次用三张样图走完整流程，确认日记 ≤100 字、服务卡类型与物品状态匹配
5. 断网重试一次，确认错误提示与重试按钮工作

## 范围边界

**做**：拍照/选图、扫描动效、一次 Claude 调用、四类服务卡渲染、基础错误兜底、两个后端单测。

**不做**：账号、历史记录、收藏、真实下单、AR 实景叠加、并发与缓存优化、多语言、自动化前端测试。
